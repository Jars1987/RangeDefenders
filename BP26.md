# Range BP26 badge demo

Breakpoint (November 15-17) ships Solana Defenders only, with no game server.
Lazarus In The Room and its server are parked. The legacy setup below documents
that parked build. Original DEF CON games under scripts/ and legacy tools/ stay unchanged.

## Defenders score posts

Every game over offers an X intent QR with this exact text:
`I scored <S> on Solana Defenders at #Breakpoint. Beat it? @range_org <CODE>`.
The URL uses form encoding (spaces as `+`) and is at most 140 bytes. A colleague's
bot reads posts tagging @range_org; the daily winner is chosen manually.

CODE is six uppercase Crockford base32 characters (`0123456789ABCDEFGHJKMNPQRSTVWXYZ`).
Hash the UTF-8 bytes of `<score>|<UTC day or 0>|sd1`
with FNV-1a: start at `0x811c9dc5`, XOR each byte, multiply by `0x01000193`,
wrapping to 32 bits after each byte. Encode the low 30 bits, most significant
character first, zero padded to six characters. This reproducible checksum is not
proof of a genuine score. `tools/bp26/defenders-code.mjs` exports `codeFor` and
prints a code when passed `<score> <utcDay>`; `--test` checks the
shared fixtures against both JS and Lua. With no arguments it runs those checks.
The bot reads the score from the post and the UTC day from the post's timestamp
(`floor(unix seconds / 86400)`), and accepts that day, the day before (a game
finished just before midnight) or 0 (a badge whose clock never synced).

UTC day is `sys.time() // 86400`; an unsynced clock tracks only the all-time best
and uses day 0 in the code. The badge stores today's and all-time bests locally.
The one-time welcome award is 25 !LAMPs, retried on a later launch until awarded.
Set `LAUNCH_TWEET_ID` in `apps/defenders/main.lua` to enable RIGHT to repost Range.
The About QR links directly to Range transaction screening with `bp26-badge` UTMs.

## Run

From the repository root, with Bun and Lua 5.4 installed:

```sh
cd server
bun install
bun test
bun run typecheck
cd ..
/opt/homebrew/opt/lua@5.4/bin/lua tools/bp26/harness.lua all
bun run demo
```

Open http://localhost:8787/ for the playable browser sim. The same process serves
http://localhost:8787/live?ns=demo for a booth screen. If 8787 is occupied it prints
the next available port through 8797. Production API only: `cd server && bun run start`.

## Play

SELECT joins an on-demand room. Five bots join automatically in the browser sim.
Preparation lasts 30 seconds, followed by a four-minute hunt. The real Lua app runs
inside Wasmoon; the browser supplies Solana OS API adapters. The other badges are
server clients with draggable positions. Close proximity builds HEAT; use SELECT
to screen the selected radar badge, UP/DOWN to choose by stable badge id. Tainted
investigators keep hunting. RIGHT self-quarantines tainted funds. LEFT opens the
install/share QR during a round. DOWN on the title starts unrewarded solo Practice.
BACK returns or asks to leave. A source must SELECT to accept its role in preparation.

The demo uses @relay as the source for repeatability. For CAUGHT, SELECT to join,
wait for the active CLEAN status, then wait 12 seconds and screen @relay. For
ESCAPED, join and keep the default nearby positions without catching the source.
Bots never screen. Drag badges apart to slow spread or follow the clues upstream.
Simulation controls hide network loss, gather, and spread presets from the normal
flow. New room starts a fresh isolated session. Demo never mints or pays !LAMPs.

Result QR opens a result page with an install link and Post on X. Install / share
is also available from the title at any time. /go/screening carries the Range UTMs.

## Public preview

The sim and server share one port. An attended operator can expose them with the
fleet wrapper after starting the demo:

```sh
tunnel 8787
```

Use the printed port if it differs. Stop the tunnel after the session. This executor
has not opened a tunnel: unattended executor runs must not create public previews.
No release, deployment, commit, or push is performed. For short result QRs, a public
result URL must fit in 40 bytes. Set SHORT_ORIGIN to a short HTTPS hostname that
routes /r/ here if a random tunnel hostname is too long. A long hostname returns
short_origin_required instead of silently violating the badge QR contract.

## Badge package

apps/lazarus/app.json declares mesh, led, lamps, profile, http and the allowed host.
Set SERVER at the top of main.lua and its matching hosts entry before publishing.
It uses only documented Solana OS widgets, neutral mesh presence below 4 messages/s,
signed HTTP at a five-second poll cadence, relative times and bounded peer lists.
Tainted LEDs are red; countdown LEDs pulse. Offline play is solo Practice only.

Welcome amount comes from server config, default 0. The title hides its reward line
when zero. Entitlements are durable per account/app/campaign. needsX prompts linking
X; award-cap exhaustion does not stop play. The organizer must fund the escrow and
approve an award cap before enabling production rewards. See server/README.md for
routes, tuning, signature validation, idempotency and reward failure semantics.

## Verification

The Lua harness loads actual main.lua in isolated environments for N badges, uses
RSSI links and deterministic mesh loss, signs fixture requests with a test Ed25519
key, and talks to the real rules/API engine on an ephemeral loopback port. Debug count hooks
enforce 200,000 VM instructions per callback; widgets enforce 64 objects and one QR.
It validates manifest name, source size, mesh payload/rate and printable UI strings.
An isolated collectgarbage("count") probe estimates retained dynamic heap with loaded code
prototypes excluded to approximate the badge's flash/XIP execution. It is not a
measurement of a real 32-bit Lua 5.5 badge; source compilation and transient heap
can differ. Latest run: 12/12 scenarios, 63,000 max instructions, 10 live widgets,
under 20 KB estimated retained heap. Aim remains <=32 KB; real hardware validation is needed.

Browser behavior and visual checks:

```sh
cd server

CHROMIUM_PATH=/path/to/chrome bun browser-smoke.ts
```

The DOM smoke uses the actual browser app.js, actual main.lua, Wasmoon and real

browser layout/video checks have not been completed here.

## Official emulator

The copied docs/bp26/EMULATOR.md describes the official firmware emulator and MEMFS
sideloading. Reference docs are MIT material from spacemandev-git/solana-os; typographic
dashes in these local mirrors are normalized to ASCII. The authoritative API is
LUA_API.md; reconciled product decisions take precedence over the older Taint game.

The public emulator page is https://solana.com/breakpoint/badge/emulator. The reliable
supported route for an unpublished app is a signed-in /apps/submit session with
Try in emulator. This run cannot authenticate or open that session. MEMFS sideload
is therefore documented as unverified, rather than claimed successful. The browser
sim here runs Lua, not the official firmware, and does not emulate LVGL, float32 or
physical radio behavior. Target firmware remains 0.5.5, Lua 5.5.

The production Worker/Durable Object adapter is scaffolded at server/worker/ and
included in typechecking. No Cloudflare account, deployment, or secrets are created.
